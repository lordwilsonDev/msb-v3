## What v3.4 Must Do

### Priority 1: SpeechFunctions (the killer feature)

Voice input → transcription → intent parsing → governed MSB execution.

This is the highest-value multimodal feature because:
- Voice is the most natural human-computer interface
- The governed execution path already exists (ActionGate → Tool → Evidence)
- Speaker verification enables identity-aware authorization
- Hands-free operation is the stated goal of the "Voice Identity Workstation"

**What needs to exist:**
1. Speech capture pipeline (microphone → audio buffer)
2. Transcription engine (local Whisper or cloud API)
3. Speaker verification (enrollment + identification)
4. Intent extraction (transcript → structured command)
5. Authorization gate (fail-closed: unknown speaker → denied)
6. Governed execution (intent → MSB ActionGate → tool → evidence)
7. Recovery (failed transcription → retry, timeout → abort)

**What already exists:**
- `SpeechFunctions.map_command()` — intent parsing (stub, but the mapping logic is real)
- ActionGate — governed execution boundary
- Speaker verification infrastructure (referenced in the architecture)
- Voice Identity Workstation architecture (documented)

### Priority 2: VisionClaw (screen awareness)

Screen capture → OCR/VLM → agent context.

Lower priority than speech because:
- Screen capture requires ScreenCaptureKit (macOS-specific)
- The agent already has text-based context
- Vision adds value mainly for debugging and monitoring

**What needs to exist:**
1. Screen capture (ScreenCaptureKit → image buffer)
2. Image analysis (VLM or local model → structured description)
3. Context injection (vision description → agent context)
4. Capture scheduling (on-demand or periodic)

### Priority 3: HapticHeartbeat (lowest priority)

System activity → tactile feedback.

This is the least practical because:
- Haptic feedback requires physical hardware (macOS trackpad/Touch Bar)
- The value proposition is unclear for a server-side system
- Could be useful for a future mobile/watch companion app

**Deferral criteria:** Defer until SpeechFunctions and VisionClaw are proven. Haptic is a "nice to have" not a "must have."

## Phase Breakdown

### Phase 1: Speech Pipeline (3 days)

The core multimodal feature. Voice in, governed action out.

| Task | What | Effort |
|------|------|--------|
| 1a | Speech capture module — microphone → audio buffer (pyaudio/async) | 0.5 day |
| 1b | Transcription engine — local Whisper (faster-whisper) or cloud API | 1 day |
| 1c | Speaker verification — enrollment + identification (resemblyzer or similar) | 0.5 day |
| 1d | Intent extraction — transcript → structured MSB command (LLM or parser) | 0.5 day |
| 1e | Auth gate — fail-closed authorization (unknown speaker → denied) | 0.5 day |
| 1f | Integration tests — full voice → execution pipeline | 0.5 day |

**Dependencies:** faster-whisper (or whisper API), resemblyzer (or similar), pyaudio
**Disk impact:** ~500MB for Whisper model weights (tiny compared to BitNet)
**Blocker:** Disk must be below 80% — currently at 71%, so this is unblocked

### Phase 2: Vision Pipeline (2 days)

Screen awareness for the agent.

| Task | What | Effort |
|------|------|--------|
| 2a | Screen capture module — ScreenCaptureKit → image buffer | 0.5 day |
| 2b | Image analysis — VLM (local or API) → structured description | 1 day |
| 2c | Context injection — vision description → agent context | 0.5 day |
| 2d | Integration tests — capture → analyze → inject | 0.5 day |

**Dependencies:** ScreenCaptureKit (macOS), VLM access (local or API)
**Disk impact:** ~1GB for VLM weights (if local)
**Blocker:** Disk must be below 75%

### Phase 3: Haptic Pipeline (1 day, deferred)

Tactile feedback — lowest priority.

| Task | What | Effort |
|------|------|--------|
| 3a | System activity monitor → pattern mapping | 0.5 day |
| 3b | Haptic output (CoreHaptics) | 0.5 day |

**Deferral criteria:** Defer if SpeechFunctions + VisionClaw aren't proven first.

### Phase 4: Integration & Governance (1 day)

Wire everything together under MSB governance.

| Task | What | Effort |
|------|------|--------|
| 4a | Unified multimodal API — single entry point for all modalities | 0.5 day |
| 4b | Governance integration — all multimodal actions go through ActionGate | 0.5 day |

## What v3.4 is NOT

- **Not a rewrite** — the interfaces exist, we're filling them in
- **Not cloud-dependent** — local inference preferred, cloud as fallback
- **Not always-on** — voice/vision are on-demand, not continuous surveillance
- **Not multi-platform** — macOS first (ScreenCaptureKit, CoreHaptics are macOS-native)
- **Not replacing text** — multimodal is additive, not a replacement

## Acceptance Criteria

### SpeechFunctions
- [ ] Can capture audio from microphone
- [ ] Can transcribe audio to text (local Whisper)
- [ ] Can identify speaker (enrolled vs unknown)
- [ ] Can extract intent from transcript
- [ ] Can execute governed action via ActionGate
- [ ] Unknown speaker → denied (fail-closed)
- [ ] Failed transcription → retry with timeout
- [ ] Full pipeline: voice → text → intent → action → evidence

### VisionClaw
- [ ] Can capture screen (ScreenCaptureKit)
- [ ] Can analyze image (VLM → description)
- [ ] Can inject vision context into agent
- [ ] Capture on-demand (not continuous)

### Governance
- [ ] All multimodal actions go through ActionGate
- [ ] Speaker identity recorded in audit trail
- [ ] Vision context logged (what was seen)
- [ ] Kill switch stops all multimodal pipelines
- [ ] Budget controls apply to multimodal API calls

## The First Real Test

Give v3.4 a microphone and say:

> "Research the latest developments in local AI inference and summarize the top 3 findings."

v3.4 must:
1. Capture the audio
2. Transcribe it correctly
3. Identify the speaker (enrolled)
4. Extract the intent (research request)
5. Execute via governed path (ActionGate → Research Assistant)
6. Return the summary
7. Record everything in the audit trail

If that works, the Voice Identity Workstation is real.
