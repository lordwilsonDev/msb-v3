## 1. EXECUTIVE SUMMARY

msb-v3 is **healthy and green**, but its architecture tells a story of **three islands**:

1. **`msb_v3/`** — the live, canonical server. Everything the running process (PID 35107,
   `:8766`) actually executes lives here. 24 API routers wired in `api/app.py`.
2. **`sovereign_runtime/`** — a real, tested "brain" (recursive planner, AIL pipeline, MoIE
   swarm, event bus). 21 tests, all passing. **Not imported by anything in msb_v3.**
3. **`personal_intelligence/`** — a real, tested "personal agent" layer (agent factory,
   context engine, memory graph, provenance, skill engine). 15 tests, all passing.
   **Not imported by anything in msb_v3.**

**Critical finding: zero cross-imports between the three trees.** They do not conflict —
they are simply not connected. The server works fine without them; they pass their own
tests in isolation. This is not "three competing personalities" — it is **one live system
plus two well-built satellites waiting to dock.**

**Second finding: the "91 dirty files" are not code churn.** 82 of them are tracked runtime
data (`data/memory_graph/*.json`, `data/msb_v3.db`, `data/triumvirate/*/PLAN.json`).
`.gitignore` lists `data/` — but the files were committed *before* the ignore was added,
so they stay tracked and churn on every run. The code tree itself is essentially clean.

## 4. GIT STATE — WHAT THE "91 DIRTY FILES" REALLY ARE

```
 79 M  (modified, tracked)
 12 ?? (untracked)
```

**The 79 modified files are overwhelmingly runtime data:**
- `data/memory_graph/kg1.json`, `kg2.json`, `kg3.json` — churn on every memory write
- `data/msb_v3.db` — SQLite, churns constantly
- `data/triumvirate/*/PLAN.json`, `artifacts/plan.json` — agent-plan state
- `data/triumvirate/hippocampus.db`, `mesh_state.json` — runtime state

**Root cause:** `data/` IS in `.gitignore`, but 82 data files were committed to git *before*
the ignore rule was added. Git keeps tracking already-committed files regardless of .gitignore.

**Fix:** `git rm -r --cached data/` (untracks, keeps files on disk) — one command, then commit.
The repo's dirty-file noise disappears overnight.

## 5. CONSOLIDATION RECOMMENDATION

### The decision: `msb_v3` stays the spine. `sovereign_runtime` is the future core.
### `personal_intelligence` is the vault-facing layer.

**Why msb_v3 is canonical:** it is what runs, what's proven, what the bridge exposes, and what
the business plan (HaaSS node, outcome engine, skill) actually calls. Nothing else is wired in.

**Why sovereign_runtime is the "future core":** its recursive-planner + AIL/MoIE brain is the
differentiator the whole stack is *named* after. It should be docked, not deleted.

**Why personal_intelligence maps to the vault:** agent factory + memory graph + provenance +
skill engine ≈ the vault's customer files, memory, and the skill_system. It's the layer that
serves the outcome-engine work we just built.

### Migration path (phased, no big-bang)

**Phase 1 (now, 30 min): clean git.**
- `git rm -r --cached data/` → commit → the 79 dirty data files stop churning
- Add explicit `data/**` + `runtime/**` confirmations to .gitignore

**Phase 2 (this week): wire sovereign_runtime in, behind a flag.**
- Add `src/msb_v3/api/brain.py` exposing `sovereign_runtime.brain.recursive_planner`
  as a `/brain/plan` endpoint (and `/brain/ail`, `/brain/moie`), default OFF
  (config flag `ENABLE_BRAIN=0`).
- The existing 21 tests stay as the safety net. No behavior change to the live server.

**Phase 3 (next sprint): make personal_intelligence the vault adapter.**
- `personal_intelligence.memory_graph` becomes the typed layer over the vault's
  `data/memory_graph/` JSONs; `provenance` stamps every outcome-engine artifact.
- Wire `/mcp` bridge tools (`vault_*`) through `personal_intelligence` so the bridge
  is backed by the typed layer instead of raw file calls.

**Phase 4 (when ready): deprecate the loose ends.**
- Move `triumvirate/` and `uac/` into `msb_v3/core/` namespaces (they're already msb_v3-internal)
- Single `src/msb_v3/` with `runtime/` (brain) and `personal/` (intelligence) sub-packages
- Update `pyproject.toml` package discovery accordingly; re-run 243 tests

### What NOT to do

- **Do NOT delete sovereign_runtime or personal_intelligence.** They're tested, valuable,
  and small. Deleting working code to "simplify" is how you lose the differentiator.
- **Do NOT merge everything into one file tree today.** Big-bang refactors of a green,
  shipping system are how you break what works.
