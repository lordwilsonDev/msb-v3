## What v3.2 Must Fix

### 1. PLEI Lifecycle Bug (BLOCKING)

The lifecycle classifier crashes:
```
AttributeError: 'str' object has no attribute 'evidence'
```
`classify_lifecycle()` receives a string path instead of a `ProjectTwin` object. This blocks all PLEI analysis. Fix is in `plei/lifecycle.py` — needs to construct the twin from the path, or the caller needs to pass a proper twin.

**Effort**: 1 hour
**Impact**: PLEI works or doesn't

---

### 2. Memory Consolidation (V5)

Three competing memory systems:
- `memory/` — original memory subsystem (0 tests)
- `memory_fabric/` — fabric-based memory (API router exists)
- `retrieval/` — RAG with Qdrant (1 test file)

These need:
1. A single documented interface (which one to use when)
2. Integration test proving the chosen path works end-to-end
3. Deprecation of redundant paths

**Effort**: 2 days
**Impact**: Eliminates architectural confusion

## Anti-Scope-Creep Rules

1. **No new subsystems** — v3.2 closes gaps, doesn't create them
2. **No new API routes** — the 234 existing routes are enough
3. **No new providers** — the 10 existing providers cover the space
4. **No distributed mesh** — single-node must be rock solid first
5. **No multimodal unless storage allows** — don't repeat the 100% disk problem

## Definition of Done

v3.2 is done when:
- All 10 verification gaps (V5, V6, V8 + 7 new) are closed with evidence
- PLEI lifecycle classifier works
- Memory has a single documented interface
- Calibration data pipeline is collecting predictions
- CI remains green throughout
- No new critical gaps introduced

## What v3.2 Is NOT

- Not a feature explosion (v3.1 already has 234 routes, 37 subsystems)
- Not a rewrite (consolidation, not revolution)
- Not multimodal-first (storage-gated)
- Not distributed (single-node must be proven first)
- Not a new architecture (the architecture is solid, just needs gaps closed)
