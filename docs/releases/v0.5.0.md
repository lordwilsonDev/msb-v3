## What changed about the verification itself

Both defects were found by running the gate rather than reading it.

### The virginity check failed before anything booted

`runtime/secret-rotation.log` was committed by a broad `git add` in `e3e91fe`
(2026-09-20). `verify-release.sh` refuses a clone containing any tracked path
under `runtime/`, so every tag cut from that commit on exited 1 at its *first*
check — before the version check, the seeding, or the boot. Nothing caught it:
`scripts/portability-check.sh` excludes `/runtime/` from its staged copy by
design, so pushes stayed green while releases could not pass. The file is now
untracked (kept on disk, so local rotation history survives) and ignored
alongside its siblings, with the virginity contract pinned in
`tests/test_release_versions.py`. The log held key *names* and a timestamp,
never a value.

### The gate ran less than it documented

The gate's selection is `-m "not live"`, but `tests/conftest.py` deselects
`integration` + `chaos` (and `live`) from any default collection unless
`MSB_RUN_TIERS=1`. So `-m "not live"` resolved to the hermetic core: the gate
booted a run-scoped server and then ran a suite whose members assume no server
is listening. `scripts/verify-release.sh` now sets `MSB_RUN_TIERS=1` on the
suite invocation — the hermetic core alone is 3563 tests here, the tiers take it
to 3626 against the server the gate provisions. Pinned by
`tests/test_release_versions.py::test_verify_release_selects_the_tiers_it_documents`.

## What changed since v0.4.2

138 commits: 27 `feat`, 46 `fix`, 21 `docs`, 17 `chore`, 6 `audit`, 4 `test`.
39 new source files, 29 new docs.

### Features

- **desktop** — Tasks panel, an SSE task stream with backoff reconnect,
  per-section re-render, and IPC validators for the task channels.
- **cron** — `alert_check` (killswitch / ActionGate-rate / health-degradation
  rules) with state persistence, `model_keepalive`, and a seeded check on
  startup.
- **governance** — capability-first hardening Phases 0-5: UNKNOWN verdict,
  registry, manifests, resolver, decision, shadow.
- **providers** — agent workers register by configuration
  (`MSB_PROVIDER_PLUGINS`) instead of being listed in the Definition's own file,
  validated fail-closed, with a swap test that changes the factory's worker
  without touching the consumer. See `docs/provider-plugins.md`.
- **wrongness** — Wrongness Engine MVP: deterministic claim falsification.
- **security** — AIB-001 P0/P0.1: the C4 key untracked, plus a
  secret-prevention gate.
- Also `vault_lint`, the `call_mlx` worker adapter, the steward project-state
  layer, and Guardian v1 (OBSERVE-only).

### Fixes worth naming

- **Tier hermeticity.** `test_cold_state_verification.py` hardcoded `tcp:8766`
  and `data/memory_fabric/memory.db` — on a developer machine it SIGKILLed
  whatever owned the port, then tested that process instead of the server under
  test. Four integration files hardcoded the deployment's memory-fabric path and
  wrote rows into it. Tests now resolve the server under test and refuse to
  signal the default port without an explicit opt-in.
- **`scripts/ci-runtime.sh` could not boot on any checkout with a `.env`.**
  Only `scripts/run.sh` sourced it, and the app fails closed when `.env` exists
  but no secret resolved. It worked in CI for the same reason the virginity
  defect hid — CI never had the file. It now loads `.env` inside a subshell
  (redirects still win, nothing leaks into the caller) and records the stores
  the server actually received.
- The blueprint citation index is drift-gated in CI.
