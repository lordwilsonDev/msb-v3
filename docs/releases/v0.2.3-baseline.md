## Phase 0.2 virgin-checkout finding (resolved)

A fresh clone ran `make test` → **1222 passed / 6 skipped** (vs 1224/4 in the
working tree). Root cause: two `tests/test_harness.py` cases skip unless the
research-runtime fixtures are seeded into `runtime/research/`
(`sovereign-ai-orchestration` run ledger + `ralph_test` STATUS.json), and
`make test` did not seed. Fixed by wiring `scripts/seed-research-runtime.sh`
(idempotent, no-clobber) into the `make test` target, so a virgin checkout now
reproduces the working tree exactly. The 4 remaining skips are opt-in live
tests (`MSB_LIVE_TESTS` / `MSB_LIVE`).

## Known limitations (carried into Phase 1+)

1. No formal DB schema versioning / migrations.
2. Dual vector stores (`api/rag.py` Qdrant vs `VectorHippocampus` SQLite+cosine).
3. Multiple ad-hoc JSON-file state stores (triumvirate STATUS/poison-pill/sbom, etc.).
4. Module-level singletons in `triumvirate/` (no dependency injection).
5. No multi-agent orchestration; single deterministic agent slice.
6. CLI agent provider is documented "best-effort isolation, not a sandbox".
7. Tenant chat LLM routing not tenant-scoped (RAG is).
8. `data/` runtime state partially git-tracked (SMI-017 #10 partial).

## Known unverified claims (to close before L7+)

1. Frontier seam: configured, never exercised end-to-end live.
2. Live signed-device path: implemented, low-volume live usage.
3. MoIE engine: code exists, not wired into the agent loop.
4. Multimodal: stub-gated, not implemented.
