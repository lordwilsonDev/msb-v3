## What changed since v0.4.0

### O1 — `release-verify` is hermetic (PRODUCTION-CLOSURE-001 P1)

- `scripts/verify-release.sh` boots a **run-scoped** msb-v3 from the clone via
  `scripts/ci-runtime.sh` (random port, own DB, torn down on exit) instead of
  borrowing a hand-managed `:8766`. `release-verify.yml` lost its
  `vars.MSB_BASE_URL` server-ensure step.
- The suite is **tiered**: `live` / `chaos` / `integration` pytest markers
  registered in `pyproject.toml`; the gate runs `-m "not live"` (3040 tests).
  Unmarked = hermetic core.
- Failing test IDs are now surfaced into the workflow log (`-rfE` +
  `_emit_failures`) — previously only a count reached GitHub.

### The bug every prior `release-verify` hit

`plei.orchestrator.ingest_all()` derived the project's identity name from the
**checkout directory basename**. A virgin-clone verify runs from
`/tmp/msb-verify-XXXX/`, so `tests/plei/test_plei_is_msb_v3.py` (3 asserts on
`name.startswith("msb-v3")`) failed. `make portability` passed only because it
stages to `/tmp/msb-v3-portable-*`. Fixed: `ingest_all` reads
`pyproject.toml [project].name` first, dir name as fallback — a project's
identity is what it declares, not where it's cloned.
